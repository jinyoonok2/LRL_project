# LRL MolmoSpaces Extensions

This package contains the long-horizon VLA tasks, policies, navigation changes,
data-generation configs, and per-door stability accounting. The pinned
`molmospaces/` checkout remains the upstream implementation plus the separately
accepted pre-VLA compatibility fixes.

## Package structure

Each package owns one stage of the workflow. CLI `main()` functions parse
arguments and call the workflow classes; small numerical helpers remain functions.

| Package | Main classes and responsibility |
|---|---|
| `configs/` | Experiment and policy configuration classes. |
| `baseline/` | `BaselineConfig` and `BaselinePipeline` run generation, split organization, speed matching, point prompts, and validation together. |
| `tasks/` | Composite tasks, target selection, and door/start-pose samplers. |
| `policy/` | `NavThenDoorOpeningPolicy` and `NavThenPickAndPlacePolicy` coordinate phases. |
| `policy/navigation/` | A* planning and `NavDoorAStarSmoothPlannerPolicy`, including short-path spline handling. |
| `datagen/` | `PerDoorRolloutRunner` schedules and saves rollouts; `ShardValidator` checks accounting. |
| `dataset/` | `DoorOpeningEpisode`, `NumberedIndex`, and `OpenedWithGraspSplit` read and organize demonstrations. |
| `quality_check/` | `OpenedWithoutGraspCheck` inspects recorded success and grasp quality. |
| `rerender/` | `SlowNavRerender` rewrites recorded trajectories; `OpeningMatchedNavRerender` uses an `OpeningSpeedProfile` to choose navigation speed. |
| `tests/` | Sampling/accounting, split, quality, navigation, and rerender regression checks. |

For door generation, read the config, task/sampler, composite policy, and rollout
runner in that order. For dataset preparation, read episode/index classes,
quality checking, splitting, and rerendering. Opening-speed measurement lives
in `rerender/opening_speed.py`, separate from rendering and dataset I/O.

## Commands

### Unified baseline

For future generation, the combined workflow uses one YAML config. Modules remain independently
usable. Preview the smoke configuration without creating outputs:

```bash
python -m lrl_molmospaces_extensions.baseline.runner \
  --config configs/nav_door_baseline_smoke.yaml --dry-run
```

Submit generation and final video preparation as one Slurm job:

```bash
BASELINE_SLURM_TIME=02:00:00 bash scripts/sbatch_nav_door_baseline.sh \
  configs/nav_door_baseline_smoke.yaml --run-id smoke_001
bash scripts/sbatch_nav_door_baseline.sh configs/nav_door_baseline.yaml \
  --shard a --run-id production_001
```

The existing `run_rby1_simple_visible_kuorobot01.sh` smoke/production modes now
use these same baseline configs on that host. Shards A–F select subsets of the
configured houses and append `_shard_a`, etc., to the run ID.

The final dataset matches navigation/approach speed to each clip's door-opening
motion during rerendering. Opening frames remain at the recorded rate. Visible
handle points and camera parameters are recomputed at each rendered pose.
Point coordinates are stored in the existing H5 observation structure; the
head-camera video gets a visible marker when `draw_point: true`. Invisible
handles have zero points. The target handle stays tied to the sampled door.

Results are grouped under `results/nav_door_point_matched/RUN_ID/`; see the
[result layout](../results/README.md). Each run saves its resolved configuration
and an atomic stage-status manifest. `--resume --run-id SAME_ID` skips completed
stages and requires the same config and shard. Partial generation or incomplete
H5/video output is reported for recovery rather than silently skipped. The
production house split is declared in YAML; the one-house smoke config has no
validation houses. Dataset validation here checks artifact alignment, not
training readiness or learned-policy success.

### Retained final dataset

`results/final/` is the existing opening-matched, opened-with-grasp dataset:
601 trajectories with two views: `house/` (432 train / 169 validation) and
`trajectory/` (511 train / 90 validation, seed 42, stratified by push/pull).
The trajectory view links to files owned by the house view; it can share houses
across train and validation. Each view has its own `index.tsv` and manifest. It was not regenerated by
the new baseline runner. Earlier dataset variants are retired. The future
baseline configs and launchers remain available when new generation is needed.

### Individual modules

Launch a fixed-attempt door evaluation with:

```bash
scripts/run_rby1_door_stability_kuorobot01.sh open-only shard-a push
```

The optional fourth argument changes the attempt count for smoke tests:

```bash
scripts/run_rby1_door_stability_kuorobot01.sh open-only same-door push 2
```

Validate a completed run with:

```bash
python -m lrl_molmospaces_extensions.datagen.validate_shard RUN_DIR \
  --expected-attempts 10
```

File successful door-open videos by grasp:

```bash
python -m lrl_molmospaces_extensions.quality_check
```

The default dataset is `data/final`. It writes `quality_check/opened_without_grasp` and `opened_with_grasp` under the selected dataset.
Failed opens are not saved by production datagen, so there is no `did_not_open` folder.

For the retained final dataset, the existing house split owns the files and
is protected against overwrite. Rebuild the linked trajectory view with:

```bash
python -m lrl_molmospaces_extensions.dataset.split --mode trajectory
```

Match navigation speed to each clip's cuRobo door-opening speed. Opening frames
stay as recorded. This writes a new tree and does not replace `slow_nav`:

```bash
python -m lrl_molmospaces_extensions.rerender.opening_matched_nav \
  --dataset PATH_TO_RECORDINGS --output PATH_TO_NEW_OUTPUT --limit 1
```

### Full validation and comparison media

`prepare_final_nav_eval.py` restores the recorded starts for all 90 trajectory-validation episodes. `run_final_nav_eval.py` runs model-controlled navigation and opening; `sbatch_final_llm_nav_eval.sh` submits nine shards with concurrency two. These are trajectory-held-out evaluations, not held-out-house tests.

Comparison export is MP4-only. To rebuild local comparisons from a completed run, then apply the existing grasp criterion:

```bash
python scripts/make_full_validation_comparisons.py \
  --results /bigtemp/xna8aw/nav_door/eval/final/trajectory/llm/full_validation_6687763 \
  --output docs/slide_history/media
python scripts/classify_eval_comparisons.py
```

The classifier organizes successful openings into `opened_with_grasp` and `opened_without_grasp` using 30 cumulative recorded grasp frames. Failed openings remain under `failure`. Shared dataset and videos are accessible through `molmobot_molmospace/dataset` and `molmobot_molmospace/media`.
